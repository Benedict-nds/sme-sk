# Need triage

Not every problem is a software problem, and not every software problem is realistic for a small business. Triage sorts honestly so the roadmap is built on what we can actually deliver. Follow the `house-rules` skill throughout.

## Categories

1. **Digital now.** A digital tool clearly solves it, it fits their budget, skills, and connectivity, and it can start in the first phase.
2. **Digital later.** Worth doing, but it depends on something first, such as cleaning up their records, an earlier phase, or more budget.
3. **Non-digital help.** The root cause is a process, people, training, or policy issue. Software would not fix it. This still counts as help: it goes to the Solutions Advisor's `non-digital-guidance` skill rather than being dropped.
4. **Not realistic.** Beyond their budget, skills, or timeline, or outside what we offer. Say why, and point to an alternative if there is one.

## Method

For each need, taken from the needs brief:

1. Restate it in one line.
2. Find the likely root cause by asking "why?" up to three times, using only evidence from the client's files.
3. Test it: if they had perfect software tomorrow, would the problem remain? If yes, it is non-digital or mixed. Split mixed needs into their digital part and their non-digital part.
4. Rate impact and effort as low, medium, or high, and say what the rating rests on.
5. If you are unsure of the category, mark it "needs confirmation" instead of guessing.

Group duplicates, and keep the list to ten needs or fewer.

## Output

Write `work/triage.md` with a table:

| Need | Root cause | Category | Impact | Effort | Evidence | Note |
|---|---|---|---|---|---|---|

Then add **Recommended first phase**: at most three items, each with a one-line reason. Do not force a digital answer where a simple process change would do better.
